# 框架问题记录（T.tile.exp/ln/abs/reciprocal/sqrt/rsqrt/pow 测试期间发现）

> 记录日期：2026-08-19
> 分支：`refine-tile-arith-unary`
> 环境：Ascend910B3（A2，dav-2201 / dav-c220），tilelang 0.1.4+7f65c533，CANN 8.5.2
> 说明：以下问题均为 7 个一元 API 测试过程中实测发现，按"真机复现方式 → 现象 → 根因（如已定位）→ 规避/建议"记录。**问题均非本任务引入**（本任务只改 docstring/文档/测试），供框架侧后续修复参考。

## 1. AscendMemoryPlanning 在 UB 超容量时段错误（崩溃而非报错）【编译期 · 高优先级】

- **复现**：pow 单 block kernel 中每核 UB 需求超过 192KB 时，`AscendMemoryPlanning::LinearScanAllocator::allocate` 段错误（signal 11），而非抛出可读错误。
  - float16：`(160×160)` 及以上崩溃，`(128×128)` 正常
  - float32：`(128×128)` 及以上崩溃，`(96×96)` 正常
  - 即三个输入/输出 buffer + pow workspace（`max(2S,1152)`）总和接近/超过 192KB 时触发
- **附带现象**：同一进程内连续编译多个 pow kernel（cache 关闭时）偶发在第 2~3 次编译期段错误（同样栈在 LinearScanAllocator），单独编译正常
- **根因**：未深入（C++ `src/transform/ascend_memory_planning.cc`），疑似 LinearScanAllocator 对超出 UB 容量的 interval 集合未防御
- **影响面**：其他算子若单片段分配的 UB 合计超容量同样可能崩溃（本任务 7 个 API 中仅 pow 触发，因 pow 有额外 workspace 需求）
- **规避**：测试全部改用 tiled kernel（每核 UB 份额安全）+ 模块级 `pytestmark = pytest.mark.forked` 隔离进程
- **建议**：`LinearScanAllocator::allocate` 增加容量校验，超限时报友好错误（如 "UB capacity exceeded"）

## 2. torch_npu 的 `torch.testing.assert_close` 默认不把 NaN 视为相等 【测试基建】

- **复现**：`assert_close_npu` 未传 `equal_nan`，对含 NaN 的 golden（如 `ln(randn 负值)=nan`）比较时约 51% 元素误报 mismatch（`Greatest absolute difference: nan`）
- **说明**：torch（GPU 版）`assert_close` 默认 `equal_nan=True`，但 torch_npu 2.7.1 实测默认**不相等**（与 `equal_nan=False` 行为一致）
- **已修复**：`testing/python/base/common.py::assert_close_npu` 补 `tol.setdefault("equal_nan", True)`，并保留调用方覆盖能力
- **提醒**：`base/common.py` 为共享文件（max/min 等套件共用），该修改对所有套件生效（行为更贴近 IEEE），如其他套件依赖"NaN 视为不匹配"需显式传 `equal_nan=False` 覆盖

## 3. `BinaryOpSpec.kernel_scalar=False / kernel_inplace=False` 语义失效 【测试基建 · 现存】

- **复现**：`testing/python/base/binary_op.py` 中
  `self.kernel_scalar = kernel_scalar or make_scalar_kernel(self.tile_op)`
  传入 `False`（意图禁用 scalar 变体）会被 `or` 吞掉，仍生成默认 factory → 测试实际执行 scalar/inplace 路径
- **影响**：cherry-pick 来的 v0 `test_tile_pow.py` 传 `kernel_scalar=False, kernel_inplace=False` 无法禁用；本任务 pow 套件为此改为自包含文件规避
- **建议**：改为 `if kernel_scalar is None: make_scalar_kernel(...) else: (kernel_scalar or None)`，使 `None`=默认 factory、`False`=显式禁用

## 4. PTO `reciprocal` 的 in-place（dst==src0）静默产生错误结果 【模板层 · 静默错误】

- **复现**：`T.tile.reciprocal(a_ub, a_ub)`，target=pto，输出全为 1.0（正确结果应为其倒数），无任何报错
- **根因**：`src/tl_templates/pto/common.h` / 3rdparty pto-isa 中 `TRECIP` 映射为 `TDIVS(dst, 1, src)`（`pto_instr.hpp:466` 注释明确"不支持 src/dst 同一地址"），in-place 时读改写竞争
- **规避**：文档约束 2 已写明"PTO 不支持原地运算"；测试用 xfail 记录（ascendc 支持原地）
- **建议**：PTO common.h 的 TRECIP 包装层对 dst==src0 做拷贝保护，或在 codegen 层拒绝别名

## 5. PTO `pow` 原地修改 src0（log 写回）【模板层 · 语义不透明】

- **复现**：`T.tile.pow(c_ub, a_ub, b_ub)` 后再次读取 `a_ub`，值为 `log(src0)` 而非原底数（ascendc 后端 src0 保持不变）
- **根因**：`src/tl_templates/pto/common.h` 的 `pow` 实现先 `TLOG(src0, src0)` 原地求对数，再 `TMUL`/`TEXP`
- **建议**：模板内先用临时 buffer 保存 src0，或在前端/文档明确该约束（本任务已在 docstring 与文档约束 4 中写明）；后续若实现修复，需同步更新测试 `test_src0_preserved`（当前 pto 侧 xfail）

## 6. PTO `pow` 特殊值语义偏离 IEEE（0^0、负底数、1^nan → nan）【模板层 · 数值行为】

- **复现**：pto：`0^0=nan`（IEEE 应为 1）、`(-2)^3=nan`（应为 -8）、`1^nan=nan`（应为 1）；ascendc 全部符合 IEEE
- **根因**：pto pow 基于 log/exp 路径（log 定义域不含 0 与负数）
- **建议**：模板增加特殊值旁路（如 x==0 且 y==0 时输出 1），或保持现状但文档明确（已写入文档约束 5）；实施修复后需更新 `test_zero_base_zero_exponent` / `test_negative_base` 的 pto 断言

## 7. PTO `reciprocal` 整数 dtype 编译通过但输出 dtype 被改写为 float32 【模板层 · 类型泄漏】

- **复现**：tensor 声明 int16/int32 时 target=pto 编译运行"成功"，但输出实为 float32（golden dtype 断言失败）；其余一元算子（exp/ln/abs/sqrt/rsqrt）整数 dtype 编译直接报错
- **根因**：TRECIP 走 TDIVS 路径，未触发 `TUNARY floatOnly` static_assert（`TUnaryOp.hpp:246`），PTO 内部以 32 位 tile 处理
- **建议**：TRECIP 增加与 TEXP/TSQRT 一致的 dtype 检查；文档已按"整数 dtype 不支持"表述（约束 2.3.1）

## 8. `T.tile.pow` 前端无大小校验 【前端 · 约束缺失】

- **复现**：dst(64) / src1(128) 大小不一致：ascendc **静默运行**（结果未定义，无报错）；pto 编译失败（tile 形状不匹配）。unary 6 API 有 Python 断言（"size must be same"），pow 没有
- **根因**：`pow` 走 `_call_intrin_with_optional_tmp`，未复用 `unary_op`/`binary_op` 的 size 断言路径
- **建议**：前端补 `math.prod` 一致性断言（与 unary 一致）；当前文档约束 2 已写明行为

## 9. AscendC `Power` int32 精度 ±1 【CANN 层 · 数值行为】

- **复现**：int32 底数 1..8、指数 0..3，约 6.3% 元素与精确整数幂差 1（如 7³ 场景），非负底数无符号错误
- **根因**：CANN Power 内部按 float32 log/exp 计算后取整（`power_common_impl.h`），不可精确表示的幂产生舍入差
- **建议**：如需精确整数幂应使用 `T.tile.pow` 的 float 路径或自行实现整数快速幂；文档约束 6 已写明

## 10. PTO `pow` 的 dst==src1 原地运算静默产生错误结果 【模板层 · 静默错误】

- **复现**：`T.tile.pow(b_ub, a_ub, b_ub)`（dst 与 src1 同一 buffer），target=pto，结果错误（实测 maxdiff=14，无任何报错）；ascendc 同场景正确（maxdiff=0）
- **推测根因**：`src/tl_templates/pto/common.h` 的 pow 中 `TMUL(dst, src0, src1)` 在 dst==src1 时读改写竞争（与 TRECIP/TDIVS 同源问题，见第 4 条）
- **影响**：文档约束 3 原声明"原地运算两后端均支持"不成立，已修正为"Ascend C 支持任意组合；PTO 仅 dst==src0"；docstring 同步。未设独立测试用例（保持全量 405 不变），真机实测记录于此
- **建议**：PTO 模板对 dst==src1 增加拷贝保护或编译期拒绝

## 11. 补充观察（非缺陷）

- v0 文档（cherry-pick 内容）的 pow dtype 表声明 int8/uint8/int16/uint16/int32/uint32/bfloat16，实测仅 ascendc f16/f32/int32、pto f16/f32；abs/exp 等声明 int16/int32 亦不支持——v0 数据未真机验证，已按实测修正
- 连续长时间运行大量 NPU 用例（几十个以上）后偶发 aicore 异常累积导致后续用例失败（已知环境现象，非代码缺陷），建议按 shape 分批执行（见 `references/dynamic-verification.md`）
- 修改 `tilelang/language/ascend_tile.py` 会触发 CI 全量 examples+pytest，注意 PR 超时风险

# 追加：T.tile.relu/leaky_relu/sigmoid/silu 测试期间发现（2026-08-21）

> 记录日期：2026-08-21
> 分支：`refine-tile-relu-silu-sigmoid`（基于 `refine-tile-arith` = 7bafd277）
> 环境：Ascend910B3（A2，dav-2201），tilelang 0.1.4，CANN 8.5.2
> 说明：以下问题为 4 个激活 API 测试过程中实测发现（probe 脚本 + pytest 全量 120 用例），按既有格式记录。**问题均非本任务引入**，供框架侧修复参考。

## 12. AscendC::Silu 原地（dst==src）静默产生错误结果——模板结构性缺陷 【CANN 层 · 静默错误】

- **复现**：`T.tile.silu(a_ub, a_ub)`（dst 与 src 同一 buffer），target=ascendc 与 pto **均错误**：64×64 float16 实测 max_diff≈2.7（ascendc）/≈3.5（pto），100% 元素不匹配，无任何报错
- **根因**（已定位，CANN `silu_common_impl.h::SiluCalcSimplified`）：
  ```cpp
  Muls(dst, src, -1);        // step1: dst = -src        ← in-place 时 src 被覆盖
  Exp(dst, dst);             // step2: dst = e^(-src)
  Adds(dst, dst, 1.0);       // step3: dst = 1+e^(-src)
  Div(dst, srcAddr, dstAddr); // step4: dst = src/(1+e^(-src))  ← 依赖原始 src，已被 step1 破坏
  ```
  step4 的 `Div` 需要原始 src，但 step1 已将其覆盖为 `-src` → 数值错误
- **对照**：`sigmoid_impl.h::SigmoidIntrinsicsImpl` 最后一步为 `Div(dst, stackBuffer, dst)`，分母来自独立临时 buffer、不依赖原始 src，故 sigmoid in-place 在 ascendc 正确
- **规避**：文档约束已写明"silu 不支持原地运算，须使用独立缓冲区"；测试用 xfail 记录两后端（`inplace_xfail_targets=["ascendc","pto"]`）
- **建议**：CANN 修复 `SiluCalcSimplified`（如先拷贝 src 或重排为 `Div(dst, src, tmp)` 模式）；TileLang 模板层可对 dst==src 别名做拷贝保护

## 13. PTO `sigmoid` 原地（dst==src）静默产生错误结果 【模板层 · 静默错误】

- **复现**：`T.tile.sigmoid(a_ub, a_ub)`，target=pto，64×64 float16 实测 max_diff≈0.98（结果≈0.5×原值附近错量级），无报错；ascendc 同场景正确（max_diff≈5e-4，容差内）
- **根因**：未深入 pto-isa 的 TSIGMOID 实现；与第 12 条同源模式（sigmoid 组合指令序列在别名下读改写竞争），但 ascendc 的 CANN 高层 API 因末尾 Div 不依赖原始 src 而幸免
- **规避**：文档约束注明"sigmoid 原地运算仅 ascendc 支持；pto 结果错误"；测试 pto 侧 xfail（`inplace_xfail_targets=["pto"]`）
- **建议**：PTO 模板对 dst==src 别名做拷贝保护，或 codegen 层拒绝别名（同第 4/10 条建议）

## 14. `T.tile.sigmoid` / `T.tile.silu` 前端无大小校验 【前端 · 约束缺失】

- **复现**：dst(64) / src(128) 大小不一致：sigmoid 与 silu 均**静默运行**（trace 期无任何断言，结果未定义）；relu/leaky_relu（走 `unary_op`/`scalar_op`）有 "size must be same" Python 断言
- **根因**：sigmoid/silu 为独立实现（`_call_intrin_with_optional_tmp` / 直接 `tir.call_intrin("tl.ascend_silu")`），未复用 `unary_op` 的 size 断言路径——与 pow（第 8 条）同类
- **建议**：前端补齐 `math.prod(dst) == math.prod(src)` 断言，与 unary 6 API 一致；当前文档约束已按"应相同（无运行时校验）"如实表述

## 15. v0 测试 spec 声明 AscendC::Relu 支持 int16/int32 不成立 【测试数据 · 编译期报错】

- **复现**：liggest 拉取的 v0 `relu_spec.supported_dtypes` 含 int16/int32，真机编译失败——CANN `Relu` Level0 intrinsic 无 int16 模板，bisheng 报 `__ubuf__ half *` 类型错误（fail 17 用例/API）
- **说明**：AscendC::Relu/LeakyRelu/Sigmoid/Silu 均**仅支持 half/float**（silu_check_common.h::DataTypeVerifyingParameters<T, half, float>）；relu 测试已删 int16/int32，其余 3 个 API v0 声明本就只有 f16/f32
- **建议**：无需改框架；v0 测试数据未真机验证（与第 11 条"补充观察"同源），后续 cherry-pick 其他 API 测试时先跑 compile 冒烟

## 16. 共享框架 in-place 测试基建增强（非缺陷） 【测试基建 · 本次新增】

- **说明**：本次为 `testing/python/base/unary_op.py` 新增 `UnaryOpSpec.kernel_inplace`（自定义 in-place kernel 工厂）与 `inplace_xfail_targets`（按 target 声明原地不支持，如 silu 双后端 / sigmoid 仅 pto）——参考 reciprocal 自包含套件的 xfail 先例，下沉为共享机制，供后续 API（如 mul_add_dst、clamp）复用
- **数据点**：4 API 原地实测——relu/leaky_relu 双后端正确（max_diff≤2e-4）；sigmoid ascendc 正确 / pto 错误；silu 双后端错误（见第 12/13 条）
- **提醒**：`test_inplace` 固定 f16（2 用例/API，l2/low_priority），保证全量每 API ≤30 的上限不被突破
