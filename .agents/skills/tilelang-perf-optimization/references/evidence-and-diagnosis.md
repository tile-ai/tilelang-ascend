# 证据与瓶颈归因

## 事实优先级

1. 当前仓库测试、公开接口、dispatch 与目标算子源码。
2. 本轮当前后端编译结果、逐 case kernel latency、profiling 报告和 trace。
3. 实际导入的 TileLang 源码、测试与 `examples/`。
4. 名为 `tilelang-performance-best-practices` 的 Skill 中带成熟度的参考资料。

低优先级资料不能覆盖高优先级实测结果。来自其他版本、其他设备或不同测量口径的数据只能形成待验证假设。

## 采集清单

每个 case 至少记录：

| 字段 | 要求 |
|---|---|
| case ID / shape / dtype / attrs | 与测试和输入清单一一对应 |
| dispatch 分支 | 从实际代码条件推导并核对 |
| kernel 标识 | 确认 profiling 命中目标编译产物 |
| latency | 同一设备、warmup、repeat、并发和计时层级 |
| 正确性 | 基线必须满足测试文件既定阈值 |
| profiling 指标 | 只记录工具实际提供的字段与单位 |
| trace 现象 | 标注发生区间，不用单张截图替代全部 case |

## 瓶颈分类

分类是对数据的解释，不是固定阈值查表。

| 类型 | 需要观察的证据 | 常见待验证假设 |
|---|---|---|
| 计算受限 | 计算执行占主导，减少搬运后仍无明显改善 | 减少运算、融合表达式、改变归约/GEMM 数据流 |
| 搬运受限 | 读写时间或带宽主导，计算单元等待数据 | 增大连续搬运、提高复用、减少 GM 往返 |
| 标量/调度受限 | 小任务、循环与地址准备占比高，计算单元利用不足 | 合并小 tile、外提不变量、减少分支或循环层级 |
| 并行度受限 | 独立任务少于可用核，或各核工作量尾差大 | 改切分轴、调整核数、拆分或合并任务 |
| launch 受限 | kernel 本体很短，端到端时间主要由固定开销组成 | kernel 融合、dispatch 合并；需同时比较 kernel 与端到端口径 |
| 混合瓶颈 | 多项证据接近或随 shape 改变 | 按 case 分支处理，一次只验证一个主要变量 |

不要仅根据算子类别判断 bound，也不要用一个 case 的指标代表全部 case。指标比例接近时，优先设计小规模对照实验，例如只改变 tile、核数或 buffer versions，观察 latency 是否按假设变化。

## 结论强度

- **实测结论**：本轮数据直接支持，可进入方案排序。
- **待验证假设**：有现象但缺少隔离实验，可形成实验方案。
- **未知**：缺少必要数据；返回采集阶段。

报告中的每条优化措施都应能追溯到其中一种结论强度。

## 输入证据与补采契约

本文件定义消费什么证据，不包含性能采集器实现。调用方自行采集或在后续 profiling 技能接入后调用它，再传入以下记录：

| 字段 | 检查要求 |
|---|---|
| 源码与环境 | 算子版本/哈希、实际导入路径、框架版本、编译配置、设备型号与 ID |
| case | ID、shape、dtype、attrs、布局、精度测试结果 |
| 调用链 | 公开入口、dispatch、构建参数、真实 kernel 名、每 case 的 launch 数及顺序 |
| 计时 | 设备侧原始字段、单位、聚合方法、warmup、repeat、并发和完整命令 |
| profiling | 原始数据位置、摘要、指标名称与单位；缺失字段明确标记 |
| 正确性 | 测试入口、reference/容差、通过与失败明细、源码对应关系 |

基线与候选必须采用相同条件和时间口径。Host/pytest 总时间不能冒充 kernel latency；涉及 host 数据准备、额外 launch 或 D2H 的方案，可另列端到端结果，并注明测量边界。

多 launch 算子必须覆盖完整目标链；AIC/AIV 并行活动不能简单求和。检查传入的聚合方法是否与 trace 和调用结构一致。无法确认则请求调用方补充映射和计时证据，不自行猜测。

缺失项按“case/字段 → 缺失或冲突 → 需要的补采/核验 → 阻塞的结论”返回。缺少逐 case 耗时、正确性基线或源码映射时，不进入确定性的方案准入。

## A2/A3 执行侧与同步补充

读取传入的生成代码，可用 `IS_ASCEND_AIC`、`IS_ASCEND_AIV` 等结构辅助识别 C/V 路径；仍需检查实际参与计算的指令和分支。两种宏都出现不等于两类核心都有有效工作。同步受限须结合 trace 等待、生成代码依赖链和同步范围确认，不以删除 barrier 后单次变快证明原同步冗余。
