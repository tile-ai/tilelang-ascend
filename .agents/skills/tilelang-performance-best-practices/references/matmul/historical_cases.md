# 旧 A2/A3 GEMM 调优记录的保留范围

本页归纳原 `cube_optimization_path.md`、`gemm_intrinsic_optimize.md` 中有区分度的
实验。旧文档未附完整设备/编译器/CANN、20 个 canonical case 列表、baseline 实现和
原始采样；下列数据仅保留为历史报告，不能视为当前主线已复现结果。此次没有上板重测。

## Expert 路线与参数

| 历史步骤 | 参数或结构 | 旧报告相对 baseline 倍率 |
|---|---|---:|
| 单缓冲 MMA | M=128, N=256, block_K=K_L1=128 | 0.64x |
| L1/L0 双缓冲 + 分层 K | block_K=64, K_L1=256, S1=S2=2 | 0.95x |
| 上述结构 + Fixed Core | 原 tiling，核内循环多任务 | 1.01x |
| 再加 Swizzle | 示例 off=3 | 0.99x |

单独加分层 K 的旧报告为下降 19.6%；两项同时改变的 0.64→0.95x 不能归因给其中
任一项。应保留“改变 buffer 份数后重算 tile”和“需要可重叠的工作”两条结论，
不把二者永远不可分割写成硬件规则。

旧文档另对比提前一轮 L0 预取与原调度，称 20 case、3 次平均：

| 调度 | 无 Fixed Core | 有 Fixed Core | 有 Fixed Core + Swizzle |
|---|---:|---:|---:|
| 原双缓冲 | 0.95x | 1.01x | 0.99x |
| 额外 L0 预取 | 0.93x | 1.01x | 0.97x |

这支持当时没有保留额外预取，不能推出 MTE2 预取或所有 L0 预取无效。旧归因称
flag 开销抵消收益，但未提供隔离测量，保留为假设。

## Developer / gemm_v0 路线

旧报告从 `K_L1=64,kL0Size=128` 的 0.44x，变为 `128,64` 的 0.51x，再加入
20 核 grid-stride 得 0.52x。可保留“调 L1 搬运粒度及内部 K 粒度，再比较任务映射”
这一路线。当前 [gemm_v0 前端](../../../../../tilelang/language/ascend.py) 已公开
`kL0Size`；删除旧文档要求编辑 `common.h` 默认值、保证无性能回退和未提供证据的
issue 承诺。当前模板还加入容量及 N 分块处理，旧倍率不能映射成当前默认性能。

## Fixed Core 的规模相关观察

旧记录在 2048 tiles 的 Expert 实验中，K=1024/2048/4096/8192 时报告节省
212.28/202.36/176.18/111.76 us，对应约 27.8%/16.1%/7.8%/2.5%。
数据本身已经不是恒定节省 200 us；它仅提示固定开销占比与单任务工作量相关。

## Swizzle 的正负案例

旧记录报告 `1024³` 的 32 tiles 约快 14.1%，`512×4096²` 的 512 tiles 约慢
18.4%，`64³` 的 1 tile 约慢 48.2%；`1009×1024²` 同样 32 tiles 却慢 16.4%。
因此不能按“18–32 tiles 一定有益”或“某个范围一律不采用”分类，也不能把相同
地址访问直接解释成 cache 冲突。应记录 shape、dtype、映射和可比测量后决定。

## 如何使用这些记录

候选参数从 [tiling](tiling_design.md)、[ownership](pingpong_design.md)、
[任务映射](task_mapping_design.md) 的当前条件推导；历史记录只用于说明曾尝试过
什么及为何需要保留对照。分析输出区分“旧报告观察”“当前源码已核对”“待验证假设”。
