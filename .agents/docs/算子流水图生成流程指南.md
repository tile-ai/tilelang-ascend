# 算子流水图生成流程指南

> 使用 `msprof op simulator` 生成 Ascend 910系列芯片的指令级流水线 trace 文件，并通过 chrome://tracing 可视化的完整流程。

## 📋 适用场景

- 生成算子的指令级流水图（instruction-level pipeline trace）
- 分析算子的 MTE2/VECTOR/MTE3 流水线重叠情况
- 定位算子性能瓶颈（如 MTE2 瓶颈、V 核利用率等）
- 生成截图用于 PR 描述或性能报告

---

## 🚀 完整流程

### Step 1: 编译算子 kernel（带调试信息）

为了让 simulator 能解析指令地址到源码行号，需要设置环境变量让 bisheng 编译器加 `-g` 参数：

```bash
cd /path/to/tilelang-ascend/examples/cann-bench/<operator>
source /path/to/tilelang-ascend/set_env.sh
export TL_CCE_DEBUG_INFO=1
```

**验证编译信息**：
- 编译成功后，生成的 `.o` 文件应包含 DWARF 调试信息
- 可通过 `llvm-dwarfdump` 检查：`llvm-dwarfdump <path-to-.o> | grep -i debug`

---

### Step 2: 准备单 case 运行脚本

> ⚠️ **关键点**：simulator 模式下 `torch.randn` 直接在 NPU 上执行会报 `aclnnInplaceNormal` 错误，必须从 CPU 生成数据再 `.npu()` 搬运。

创建 `_run_single.py`（示例）：

```python
"""单 case 运行脚本，用于 msprof op simulator 生成流水图。

使用小 shape 避免 simulator 太慢（[128, 128] = 16K elements）。
从 CPU 生成数据再 .npu() 搬到 NPU（simulator 模式下 torch.randn 直接在 NPU 上执行会报 aclnnInplaceNormal 错误）。
选择 p=1（L1 范数，最简单的 abs + reduce_sum 组合）。
"""
import sys
sys.path.insert(0, "/path/to/tilelang-ascend/examples/cann-bench/<operator>")

import torch
import tilelang
tilelang.disable_cache()

from <operator_module> import <kernel_function>

# 参数（选择小 shape 避免 simulator 太慢）
batch = 1
N = 16384  # 例如 128 * 128
block_N = 8192
launch_cores = 1  # 单核，避免多核解析崩溃
dtype = "float16"

# 从 CPU 生成数据
torch.manual_seed(0)
a_cpu = torch.randn(batch, N, dtype=torch.float16, device="cpu")
a = a_cpu.npu()

# 编译并运行 kernel
kernel = <kernel_function>(batch, N, block_N, launch_cores, dtype=dtype)
b = kernel(a)
torch.npu.synchronize()
print("done", b.shape, b.dtype)
print("result:", b.cpu())
```

---

### Step 3: 运行 msprof op simulator

```bash
msprof op simulator \
  --soc-version=Ascend910B3 \
  --kernel-name="main_kernel" \
  --output=./output \
  python _run_single.py
```

**参数说明**：

| 参数 | 必填 | 说明 | 示例 |
|------|------|------|------|
| `--soc-version` | ✅ | Ascend 芯片型号 | `Ascend910B3`（A2 芯片）<br>`Ascend910_9362`（A3 芯片） |
| `--kernel-name` | ✅ | TileLang JIT kernel 函数名 | `"main_kernel"`（固定） |
| `--output` | ✅ | 输出目录 | `./output` |
| 最后参数 | ✅ | 执行的 Python 脚本 | `python _run_single.py` |

**运行时间参考**：
- 小 shape（16K elements，单核）：~30秒
- 大 shape（>100K elements）：几分钟到几十分钟
- 多核 persistent kernel：可能超时或解析崩溃（见 Step 4）

---

### Step 4: 核心问题及解决方案

#### ❌ 问题 1: 48 核 persistent kernel 导致 simulator 解析崩溃

**错误日志**：
```
[ERROR] InitProfConfig Get Init data failed
```

**原因**：
- 48 核 persistent kernel 包含复杂的 T.serial 循环和多核调度逻辑
- simulator 在解析阶段无法处理这种复杂的执行流
- Trace 文件过大或结构不完整

**解决方案**：用简化版单 block kernel 替代

```python
# 修改 kernel 调用，使用 launch_cores=1
kernel = <kernel_function>(batch, N, block_N, launch_cores=1, dtype=dtype)

# 或者创建一个简化版 kernel（去掉 persistent 逻辑）
@tilelang.jit(pass_configs=pass_configs)
def <kernel_function>_simple(batch, N, block_N, dtype="float16"):
    # 去掉 launch_cores 参数和相关的 T.serial 循环
    # 只处理一个 tile
    ...
```

**验证**：修改后 simulator 应在几秒内完成，输出完整的 trace.json

---

#### ❌ 问题 2: aclnnInplaceNormal 错误

**错误日志**：
```
RuntimeError: aclnnInplaceNormal is not supported in simulator mode
```

**原因**：
- simulator 模式下不支持原地随机数生成操作
- `torch.randn(..., device="npu")` 会触发 aclnnInplaceNormal

**解决方案**：从 CPU 生成数据再搬运（已在 Step 2 实现）

```python
# ❌ 错误方式
a = torch.randn(batch, N, dtype=torch.float16, device="npu")

# ✅ 正确方式
a_cpu = torch.randn(batch, N, dtype=torch.float16, device="cpu")
a = a_cpu.npu()
```

---

#### ❌ 问题 3: soc-version 选错

**错误**：
- A2 芯片用了 `Ascend910_9362`（A3 型号）
- A3 芯片用了 `Ascend910B3`（A2 型号）

**解决方案**：确认硬件型号

```bash
# 查看硬件型号
npu-smi info | grep "Chip Name"

# A2 芯片示例输出
Chip Name       : Ascend 910B3
# 对应 --soc-version=Ascend910B3

# A3 芯片示例输出
Chip Name       : Ascend 910_9362
# 对应 --soc-version=Ascend910_9362
```

### Step 5: 获取输出文件

simulator 跑完后，输出目录结构：

```
output/
├── OPPROF_<TIMESTAMP>_<HASH>/
│   └── device0/
│       ├── tmp_dump/
│       │   ├── profile_aiv_log0.toml    # per-block cycle 数据
│       │   ├── profile_aic_log0.toml    # per-block cycle 数据（AIC）
│       │   └── config/
│       └── simulator/
│           ├── trace.json               # ← 完整流水线主文件
│           ├── visualize_data.bin       # MindStudio Insight 格式
│           ├── core0.cubecore0/
│           │   └── trace.json           # Cube Core 0 流水图
│           ├── core0.veccore0/
│           │   └── trace.json           # Vec Core 0 流水图
│           └── core0.veccore1/
│               └── trace.json           # Vec Core 1 流水图
```

**关键文件**：
- `simulator/trace.json`：完整流水线（包含所有 core）
- `simulator/core0.cubecore0/trace.json`：Cube Core 0（如果有 matmul）
- `simulator/core0.veccore0/trace.json`：Vector Core 0
- `simulator/core0.veccore1/trace.json`：Vector Core 1（VEC_NUM=2 时）

### Step 6: 查看流水图

#### 方式 A: chrome://tracing（推荐）

1. **打开 Chrome 浏览器**
2. 地址栏输入：`chrome://tracing`
3. 点击 **Load** 按钮
4. 选择 `trace.json` 文件（可以是完整的或 per-core 的）
5. 查看流水线图

**流水线阶段说明**：

| 阶段 | 纵轴标签 | 说明 |
|------|---------|------|
| SCALAR | SCALAR | 标量计算（控制逻辑） |
| FLOWCTRL | FLOWCTRL | 流程控制（循环、分支） |
| MTE2 | MTE2 | GM → UB 数据搬运 |
| VECTOR | VECTOR | V 核计算 |
| MTE3 | MTE3 | UB → GM 数据搬运 |

**理想流水线图特征**：
```
MTE2   [####][####][####][####]  ← GM → UB 搬运
VECTOR [    ][####][####][####][####]  ← V 核计算（MTE2 后开始）
MTE3   [       ][    ][####][####][####]  ← UB → GM 搬运（VECTOR 后开始）
```

**重叠度评估**：
- 理想情况：MTE2、VECTOR、MTE3 三段高度重叠
- MTE2 瓶颈：MTE2 段之间有空隙，VECTOR 在等待
- V 核瓶颈：VECTOR 段很长，MTE2 在等待

#### 方式 B: MindStudio Insight

1. 下载 MindStudio Insight 工具
2. 导入 `simulator/visualize_data.bin`
3. 交互式查看流水线图

> ⚠️ 需要 MindStudio 客户端，适合深度分析

---

### Step 7: 截图并上传

#### 截图指引

1. 在 chrome://tracing 中打开 trace.json
2. 使用鼠标滚轮缩放，直到能看清完整的流水线
3. 使用鼠标拖拽移动视图，确保关键部分在屏幕中央
4. 使用系统截图工具截图：
   - Windows: `Win + Shift + S`
   - macOS: `Cmd + Shift + 4`
   - Linux: `gnome-screenshot` 或 `flameshot`

**截图要求**：
- 分辨率：≥ 2048×1024 像素
- 格式：PNG
- 文件命名：`流水图-<core-name>.png`
  - `流水图-cubecore0.png`（如果有 matmul）
  - `流水图-veccore0.png`
  - `流水图-veccore1.png`

#### 上传到 GitHub PR

1. 打开 PR 编辑页面
2. 找到流水图章节（搜索 `<粘贴截图 URL>`）
3. **将 PNG 文件直接拖拽到 PR body 编辑器中**
4. GitHub 会自动生成类似 `![image-name](https://github.com/user-attachments/assets/...)` 的 markdown
5. 将生成的 URL 替换占位符：

```html
<!-- 替换这三行 -->
<img width="2048" height="1024" alt="Cube Core 0 流水线" src="https://github.com/user-attachments/assets/xxx1" />
<img width="2048" height="1024" alt="Vec Core 0 流水线" src="https://github.com/user-attachments/assets/xxx2" />
<img width="2048" height="1024" alt="Vec Core 1 流水线" src="https://github.com/user-attachments/assets/xxx3" />
```

## 📊 常见问题汇总表

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| `aclnnInplaceNormal` 错误 | simulator 不支持原地随机数 | 从 CPU 生成数据再 `.npu()` 搬运 |
| `InitProfConfig Get Init data failed` | 48 核 persistent kernel 太复杂 | 用简化版单 block kernel（launch_cores=1） |
| soc-version 选错 | A2/A3 型号不匹配 | 用 `npu-smi info` 确认硬件型号 |
| kernel 编译没带 -g | 缺 `TL_CCE_DEBUG_INFO=1` | `export TL_CCE_DEBUG_INFO=1` 后重新编译 |
| simulator 运行太慢 | shape 太大或多核 | 减小 shape（如 [128, 128]）或使用单核 |
| trace.json 为空 | kernel 未执行或执行失败 | 检查 Python 脚本输出，确保有 `torch.npu.synchronize()` |
| chrome://tracing 打不开 trace.json | JSON 格式错误或文件太大 | 检查文件大小，太大时用 per-core trace |

